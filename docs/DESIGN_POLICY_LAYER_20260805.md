# 后半程设计：Eric Policy 决策层（2026-08-05）

> **命题**：系统已能回答「现在是什么环境」（状态/结构/波动/持仓），但不能回答「**在这个环境该做什么**」。
> `eric-policy.md` 恰好是一份完整的 condition→action 政策，且它的 §0 接口契约**本身就是一份精准的缺口清单**。
> 本文设计如何把它接成系统的后半程。
>
> **产出方式**：7 路并行设计（regime映射 / location / signals / 决策引擎 / 持仓账户 / 回测验证 / 分期集成）
> → 7 路独立对抗评审 → 监工综合定夺。评审判定全部 NEEDS_REVISION，共 **33 条 P0**——
> 本文已按 P0 修正，凡与初稿不同处均标注「评审推翻」。原始材料见 `docs/research/policy_design_20260805/`。

## 1. 缺口分析：policy §0 要什么，我们有什么

| policy §0 输入 | 现状 | 性质 |
|---|---|---|
| `regime` 五态 | 有五态但**不同组**：我们是 `squeeze`/`high_vol_chop`，policy 是 `turning_unconfirmed`/`breakout_alert` | 需**映射层** |
| `location`（at_support/at_resistance/middle_zone + 关键位） | **完全没有** | **最大缺口**——「关键位置」四个字全在这 |
| `key_levels`（前高低、EMA21/55/100/200、区间上下沿） | 只有最近一对枢轴 + EMA50/200 | 需补建 |
| `signals`（超买超卖 / 背离 1-3 级 / 反转爆量 1-2 级） | cRSI 有超买超卖 + 背离（**无分级**） | 需补分级与爆量 |
| `position` / `account` / `position_building` | **完全没有** | 决策层的必要输入 |
| `emotional_flags` | 无 | Hermes 侧可接 |

**三个已确认的接点**：
1. **我们的 `squeeze` 天然就是 policy 的 `breakout_alert`**——§7 明写突破预警的代理是「布林带宽度/ATR 收敛至历史分位低点」，我们的判据 `bbw_rank<0.15 且 atr_rank<0.30` 逐字命中。
2. **非对称迟滞 ≠ 右侧确认**。迟滞是**时间条件**（连续 N 根），P09/P12 是**价格路径条件**（突破→回踩不破 / 跌破→反弹测试失败）。两者正交，迟滞不能替代它。
3. **policy §9 自述「胜率/盈亏比尚未经独立回测验证，这是消费方接入后应做的第一件事」**——与本项目「阈值须回测校准」铁律同频，直接决定了分期路线。

## 2. 架构总则（不可协商）

```
regime/policy/            ← 新包，纯消费者，依赖单向：policy → classify/features/storage（只读）
  mapping.py    宿主五态 → policy 五态
  location.py   关键位带 + at_support/at_resistance/middle_zone
  signals.py    超买超卖 / 背离分级 / 反转爆量 / confluence 计票
  engine.py     §2 矩阵 + §3 门槛 + §5 持仓管理 + §6 否决层
  state.py      position / position_building / account（事件溯源）
data/policy.db            ← 独立库（不污染 market.db 的迁移扳机与 WAL 快照假设）
```

- **绝不修改 `classify.py` 的五态定义或 RULES_VERSION 语义**。policy 层在其上，不反向依赖。
- 三条独立版本线：`POLICY_VERSION`（矩阵/管线）、`POLICY_THRESHOLDS_VERSION`（阈值代）、`LOCATION_VERSION` / `SIGNALS_VERSION`（测量层）。
- **系统永不下单**。输出止于「建议 + 完整理由链 + 溯源编号」，执行由人。

## 3. 七层设计要点（已按评审 P0 修正）

### 3.1 regime 映射

**结构**：宿主态给动力学形态 + policy §1 的 EMA200 硬门仲裁 + 矛盾落入 `turning_unconfirmed`。

- 不直通（EMA200 在我们这里是 direction 的 0.10 软票，被平均掉了，产生不出「矛盾」→ TU 永远为空 → 砍掉 policy 引用最密的多头剧本 S2 与 S15 抄底入口）。
- 不重算（会造成判定双源——正是 08-05 一致性专项抓到的第一号病灶簇）。
- `squeeze` → `breakout_alert`，且拆成**持续态 + 边沿事件 `alert_fired`**（与 §2.5 两段式原文同构；持续态每根 WAIT，边沿触发一次 RISK_CHECK）。
- `high_vol_chop` → `range` 底座 + 置位 §6.5 `extreme_env`。

**评审推翻三处**（已修正）：
1. ❌ 初稿的 TU「中转闸」只能拦一根（第二根 `prev_policy` 已变 TU 就跳过闸门）→ 改为**闩锁 `tu_from`**：进入 TU 时记住原方向，只要反向映射持续存在就一直留在 TU。
2. ❌ 初稿的 `TU_MAX_BARS` 超时逃生阀**直接违反 §1 硬规则**——policy 里不存在「等够 N 根」替代价格测试的通路，它对"确认迟迟不来"的答案就是继续 WAIT。→ **删除逃生阀**，TU 无限期持续是正确行为。
3. ❌ 初稿 `extreme_env` 取 block（禁一切 OPEN）→ 评审实测：映射为 trend 的行里 **15-16% 被该 veto 命中**，禁掉的正是 §2.2 的 S1（policy 自称引用最密的剧本）。而 §6.5 原文是「频率与仓位主动下调」= **throttle 不是 block**。→ 改 throttle（降频降仓），不擅自加严。
4. ❌ EMA200 算不出时初稿落 `range`（把缺失伪装成可交易状态，撞铁律3）→ 改为**走 §0 降级**：不输出 policy regime，只跑 §5+§6。

### 3.2 location 层（最大缺口）

**纯测量层**，独立于 classify，不读 regime。核心是**关键位带（zone）而非点**：历史枢轴 + EMA21/55/100/200 + 区间上下沿三类原料，按 ATR 归一距离聚类成带，带上记触碰数/共振类型数。

- `at_support/at_resistance/middle_zone` **只依赖 ATR 归一距离与方位**；strength 公式（未验证的启发式）**不进判定路径**，只做排序与展示。
- **角色反转**（§2.2「原支撑变压力」）用「level 建立时的原始角色 vs 当前价格方位」纯函数实现，不用状态机。
- 落库（新表 + version 列），理由：本项目已踩过「面板与入库窗长不一致导致同一根 bar 两个读数」的坑；落库让 point-in-time 可复现结构性成立。

**评审推翻三处**：单链接聚类无宽度上限会让 zone 宽度爆炸（需加上限 + 改判据）；`at_support/at_resistance` **缺「来向」**——policy 的「**回踩至** EMA21/55」是路径语义，不是静态距离（必须补 approach 方向）；角色反转的 role 过滤器在初稿伪码里是死代码。

### 3.3 signals 层

- **超买超卖用 cRSI 自适应带作主口径**，RSI14 落库作影子。依据是设计者实测：4h `trend_down` 桶里 1h RSI14>70 只占 0.3%~4.0%（同周期口径 0.00%~1.45%），**用固定 30/70 会让 policy 引用最密的 S1 剧本结构性失效**；cRSI 带在同批 bar 上给 15.7%~25.0%。
  ⚠️ **评审对此条判 P0「证据被单边选取」**——这是本设计最需要你裁决的技术分歧，见 §5 Q2。
- **背离分级**：`anchored + max_gap_bars=20` 读法（strict_chain 在 5 品种 × 3 周期 × 4 万根里只产生 7 个三级事件，等于让 §2.1 最后一行变死代码）。**分级是风险语言不是方向指令**——三级顶背离触发的是「禁开多 + 收紧持仓」。
- **confluence 用计数制不用加权**（原文是「计票」「四个看空的逻辑凑齐了」；加权要凭空造没有出处的权重）。
- **1h 是我们的最细周期**，policy 要 3m-1h。阶段一用 1h（仍在 policy 区间内），15m 留待阶段二且只对核心池。

### 3.4 决策引擎

**可序列化规则表 + 无 I/O 纯函数求值器**：矩阵行是数据（rule_id / 溯源编号 / 优先级 / 目标规格 / 建仓方式 / 路线），谓词是**三态**纯函数（真/假/**算不出**），整表哈希成 `matrix_digest` 随每条决策入库——「为什么」永远可回答、可 diff、可复现。

**管线**（固定顺序）：
```
数据闸 → 否决层预扫(scope化) → §5 持仓管理先跑 → §2.5 RISK_CHECK
      → §2 矩阵匹配 → §3 五道 GATE(全跑不短路) → 修饰类否决 → Route A/B 锁定 → 输出+落库
```

- **否决层 scope 化**：§6 的九条限制的全是「开/加/放宽」，无一条要求别砍仓——任何 veto 都**不得阻断** CLOSE / PARTIAL_TP / TRAIL / 收紧止损。（这是对原文「覆盖 §2-§5 一切动作」的解释，见 §5 Q5。）
- **默认 shadow 模式**：OPEN_* 提案照算照记，对外降级为 `WAIT(WAIT_CALIBRATION)`——直接执行 policy §9。
- **WAIT 是常态**：政策卡输出「环境回执 + 九条 veto 灯 + WAIT」，不做「已等待 N 根」的秒表（那正是 §6.3 踏空否决要防的心理）。

**评审推翻七处**，其中致命两条：`range` 行因谓词写法**永久不可开仓**；gate 结果落库顺序错导致**记录的不是实际输出**。

### 3.5 持仓账户层

**关键洞察**：policy 要的 9 个字段里 **6 个是纯意图**（止损/Route/批次预算/决策 id——交易所永远给不出），只读 API 最多解决 3 个事实字段，却要引入密钥面与「账户权益进第三方 LLM 上下文」的隐私面。→ **Phase 1 纯手工录入 + 预留对账槽**。

- **事件溯源**：`pos_event` 追加不改（ts / known_at 双时间轴），`position` / `position_building` 是可重放的派生态。
- **止损单调性**（§5「绝不因预测正确取消风险控制」）做成**写入期硬约束**：放宽止损直接 ABORT，要放宽只能平仓重开（新 pos_id、R 归零、历史完整）。
- **现货与合约完全分账**（§6.6 明文）。
- **权益绝对值默认不进 `<panel>`**，只给 R 倍数与百分比。

### 3.6 回测验证

**新建 p4 协议**（`regime/policy_backtest.py`），不扩展 p3——两者评估单元（bar vs trade）、目标（标量分布 vs 路径实现）、评分（proper score vs 重尾统计）、依赖结构全不同。复用 p3 的锁箱常量 / 网格断言 / ledger / 代码摘要。

- 严格因果两阶段重放：**t 收线决策、t+1 开盘成交**；bar 内止损/目标双触**一律悲观取止损**（无细粒度周期时）。
- 高 WAIT 率系统的评估重心从「胜率」移到**门槛漏斗 + 动作分布 + R 分布 + 零假设对照**——尤其「位置-only」与「信号-only」两个消融，**直接检验 P06「位置+信号共振」这条 policy 的核心主张**。
- 主评估周期 4h（1h 的 15bps 往返成本 = 0.11-0.25R，与要检测的效应同量级）。
- 样本量诚实交代：4h 全库约 430 笔原始交易、有效 60-100 笔——**只够看符号，不够看数值**。

### 3.7 分期路线

| 期 | 交付 | 放行门槛 |
|---|---|---|
| **期 0** | 只装配 `PolicyInput`（mapping + location + signals 落库），**不出任何动作** | 三层读数在面板上被人工核对两周无系统性错误 |
| **期 1** | 只跑 §5 持仓管理 + §6 否决层，**OPEN_* 计数硬为 0**（policy §0 的合法降级） | 手工持仓录入跑满一个交易月；漏填率 <30% |
| **期 2** | p4 回测 + 信号阈值校准（policy §9 要求的「接入后第一件事」） | 见 §5 Q4 的预先约定 |
| **期 3** | 开放 OPEN_* **建议**（仍不下单） | 期 2 的零假设对照全部通过 |
| **期 4** | §8 长周期覆盖层 + 锁箱样本外验收 | 锁箱开箱仪式（顺带关掉 GAPS E7） |

**每期只放开一个新能力**——直接对齐 GAPS E4 的教训（每周复跑首跑同时变三个变量必得伪趋势）。

## 5. 需要你裁决的六个问题

**Q1 主周期定 1d 还是 4h？**（影响最大的一条）
- 1d 的理由：§8 两条覆盖层都锚在日线，主周期选 1d 才能与 §1 共用同一个 EMA200；1d 主 + 1h 信号的 24 倍跨度最接近 policy 原生比例。
- 4h 的理由：§2.2 有「扛单 65.5 小时」的反面案例，说明 Eric 实际时间尺度是小时级；且 4h 与回测 HORIZONS 匹配。
- **我倾向 4h 作决策周期、1d 作 regime 底座**（两者不必同一个）。

**Q2 超买超卖用 cRSI 自适应带，还是 §7 字面的 RSI(14) 30/70？**
- 设计者实测支持 cRSI（RSI14 固定阈值会让 S1 剧本几乎不触发）；但**评审判此条 P0「证据被单边选取」**。
- **我的建议：两者都落库，主口径的选择交给期 2 回测裁决**——这正是「阈值须回测」的标准动作，不必现在拍。

**Q3 锁箱污染怎么办？**（评审发现的真问题）
- 锁箱 `2026-09-01` 已在计时，而期 1/2/3 全程活在锁箱期内——期 4 再拿这段数据当「处女数据」做样本外验收就不成立了。
- 候选：(a) policy 层另设更晚的锁箱（代价：更少的处女数据）；(b) 共用日期 + 独立开箱额度 + 新建 `lockbox_openings` 闸门；(c) 期 1-3 只用锁箱前数据。
- **我倾向 (b)**，但要接受：到 2027 年初箱内数据只够证伪、不够确立胜率。

**Q4 若期 2 回测显示 policy 无统计优势，怎么办？**
- **必须现在就约定**（事后再谈会变成为结果找台阶）：合法结局是**停在期 1**（§5+§6 的纪律层本身有价值）并入档，**不是「调阈值再试」**。
- 请确认你接受这个可能的负结论。

**Q5 否决层 scope 化（veto 不阻断减仓/止损）批不批？**
- 逐条读 §6.1-§6.9，九条限制的全是「开/加/放宽」；无差别套用会让「报复交易否决」去拦一次止损收紧，反转其意图。
- 但原文字面写的是「覆盖 §2-§5 一切动作」，**这是我的解释，需要你批准**。

**Q6 现货/合约的 1% 风险各算还是全局？**
- 分账户各 1% 与 §6.6「不得混算」一致、实现最干净，但同时持仓时总敞口实际是 2%。
- 备选：设 `GLOBAL_RISK_CAP`（如 1.5%）只告警不定仓。

## 6. 风险与刻意不做

**最可能出错的三处**：
1. **用户把建议当指令**——防护：shadow 模式 + 「建议/不下单」贯穿全部输出 + 每条决策带完整 GATE 通过情况。
2. **过度交易**——policy 的特征是高 WAIT 率；防护：不做 WAIT 计时器、不做推送、政策卡默认折叠。
3. **未校准信号被当成已验证**——防护：`SIGNALS_CALIBRATED=False` 做成硬闸，未校准期一切 OPEN_* 降级 WAIT。

**刻意不做**：自动下单、实时推送、多策略并行、整数关口（v1）、加权 confluence、3m 周期采集、模型判断进风控路径。

## 附：本设计的诚实边界

- policy 的**动作逻辑与风控参数**（1%、1.5R、1/2-1/3、右侧确认、DCA 分批）置信度高，可直接执行。
- policy 的**信号阈值**是代理猜测（§7 自述），上线前必须校准。
- policy 的**胜率/盈亏比从未被独立验证**——我们的期 2 就是干这件事，且**可能得出否定结论**。
- `turning_unconfirmed` 作为「趋势反转强制中转站」是**设计推论**，policy 原文只给了 TU 两个来源，§2.2「跌破支撑瞬间→等反弹测试失败」这段等待期的 regime 归属是原文留白，我们填成 TU。这是空洞填补而非原文实现。
