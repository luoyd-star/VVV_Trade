# 前瞻账本协议（冻结于落库之前）

> **本文件的唯一目的：在任何数据积累之前，把"要验什么、怎么算、什么算通过"钉死。**
> 先看数据再挑指标，就是 p-hacking——绕多远都是。
>
> 冻结时间：见文末 `FREEZE_TS`。此后本文件的**断言与判据部分只能追加，不能修改**；
> 若确需修改，必须新开 v2 协议并**重新开始积累**，旧数据不得并入。

---

## 0. 为什么要有这个东西

系统的阈值（`0.60 / 0.30 / 0.15 / 0.30 / 0.85`、cRSI 自适应带、迟滞 2/3 根）
从设计日起从未校准过，也无法校准——**没有任何反馈告诉我们它们对不对**。

用户已裁决**不做回测**。这个裁决是对的：历史数据里已经含着答案，
拿它调参必然得到一套"完美解释过去、对未来一无所知"的参数。

前瞻账本是另一条路：**先把话说死，再等结果。** 记录在结果存在之前写下，
时间本身强制诚实。这与预注册临床试验是同一个机制。

---

## 1. 三条不可违反的纪律

### 1.1 全分母
**每个品种 × 每根已收盘 4h 都记**，包括 `middle_zone`、包括 warmup 未满的、
包括数据降级的。不许只记"看起来有戏的"。

违反的后果：三个月后会得到"armed 的表现很好"——但那只是因为没记
那些看起来不行、结果却走对了的。**选择偏差会伪装成好消息。**

### 1.2 追加不可覆盖
判断行一旦写入**永不修改**。结果只能写进独立的结果列/行。
`RULES_VERSION` 升版**不重算已有账本行**——账本记录的是"当时的系统说了什么"，
不是"现在的系统会说什么"。这与 `regime_history` 的"升版即重算"是**相反**的纪律，
必须分开两张表。

### 1.3 因果
结果计算在 T+H 时刻只能使用 ≤T+H 的数据。照抄
`regime/classify.py::rolling_states_missing` 的 walk-forward 范式，
并由 `tests/` 里的因果测试守住。

## 2. 冻结的断言

### H1（主断言，约 30 天可验）

> **在价格进入 4h 关键区间的样本中，"4h cRSI 处于极值区"的一组，
> 其后续 3 天对该区间的最大不利穿越深度，显著浅于"4h cRSI 在带内"的一组。**

- **总体**：所有 `at ∈ {at_support, at_resistance}` 的账本行
- **分组**：`main_ok = true`（cRSI 极值）vs `main_ok = false`（带内）
- **结果量（连续，非二值）**：`mae_zone_atr` = 进入后 18 根 4h 内，
  价格相对区间**不利边界**的最大穿越深度，以进入时的 ATR 为单位。
  支撑区量向下穿越 `zone_lo`，压力区量向上穿越 `zone_hi`；未穿越记 0。
- **方向预设**：`main_ok=true` 组的 `mae_zone_atr` **更小**
- **效应量门槛**：Cohen's d ≥ 0.30
- **检验**：去市场因子后的品种内配对；序贯检验（alpha-spending，α=0.05 双侧，
  80% 效力）

**为什么用连续量而不是"守住/没守住"**：二值只有 1 bit，
把"差 0.1 个 ATR"和"崩穿 3 个 ATR"当成同一件事。实测连续量约省 2.2 倍样本。

**H1 若不成立意味着什么**：4h cRSI 主票没有起到它被赋予的作用，
应当从**必要条件**降级为**加分项**。这正好回应"系统始终 WAIT"的问题——
门槛不是越严越好，是要严在有用的地方。

### H2（次断言，样本较慢）

> **GATE 1 判为"止损过紧"（ratio < 1.0）的样本，其后续 3 天内
> 最大不利偏移触及结构止损的比例，显著高于 ratio ≥ 1.5 的样本。**

- **结果量**：`stop_hit`（二值）+ `mae_atr`（连续，用于效应量估计）
- **方向预设**：ratio 小的组 `stop_hit` 比例更高
- **效应量门槛**：比例差 ≥ 15pp

**H2 若不成立**：GATE 1 的 `IV × √(期限/365)` 口径没有预测力，
止损宽度校验需要重新设计（或降级为纯展示）。

### 明确不验的

- **不验盈亏与胜率**：没有入场/出场/成本规则（5m/15m 触发层已裁决暂缓），
  任何收益类结论都不成立
- **不做参数搜索**：本协议只验上述两条**预先指定**的断言。
  想验别的必须新开 v2 协议、重新积累

## 4. 判据（读数据之前就定死）

| 结论 | 条件 |
|---|---|
| **H1 成立** | 序贯检验在 α=0.05 下拒绝原假设，且方向与预设一致，且 d ≥ 0.30 |
| **H1 不成立** | 序贯检验在预设最大样本处未拒绝，或方向相反 |
| **H1 无结论** | 样本未达最小量（每组 ≥ 60 个独立事件）时一律"无结论"，**不许解读趋势** |

**中途不许改判据。** 若数据显示某个未预设的分组更"显著"，
那是发现，不是结论——只能写进下一版协议的假设，不能当本轮的结果。

## 5. 与既有表的关系

| 表 | 用途 | 能否作阈值证据 |
|---|---|---|
| `regime_history` | 状态历史，**升版即重算** | ❌ 会被重算，非 point-in-time |
| `setup_history` | 机会轨迹派生缓存，**升版即重扫** | ❌ 事后算出来的，拿它补结果=变相回测 |
| `forward_ledger` | **本协议的账本**，追加不可覆盖 | ✅ 唯一 |

三路独立研究（2026-08-08）在这一点上完全一致：
**用 `setup_history` 补算未来结果再调阈值，等于绕过"不做回测"的裁决。**

## 6. 已知局限（写在前面，免得事后自我安慰）

1. **效应量是天定的**。若 cRSI 主票的真实增益只有 3-5pp，
   在可预见的未来都证不出来——**那本身也是结论**：这道门槛不配当必要条件
2. **85 个品种的有效独立维度只有约 7**（实测参与比法）。
   去市场因子后回收到约 8.3，仍远小于名义品种数
3. **本库历史已被污染**：设计本协议期间已在库上跑过大量测量
   （五态占比、转移矩阵、cRSI 分布、迟滞回头率等），
   所以**历史数据不能用于验证本协议的断言**，只能用前瞻数据
4. 结果期限固定 6/12/18 根，**不是**最优出场——它只衡量"位置有没有起作用"，
   不衡量"这笔交易赚不赚钱"

## 7. 冻结

```
PROTOCOL_VERSION = "fl1"
FREEZE_TS        = 见 meta 表 forward_ledger_freeze_ts（首次启用时写入）
MIN_EVENTS       = 60        # 每组最小独立事件数，未达则一律"无结论"
HORIZONS         = (6, 12, 18)   # 4h 根，对应 1/2/3 天
EFFECT_D_MIN     = 0.30      # H1 的最小效应量
EFFECT_PP_MIN    = 0.15      # H2 的最小比例差
```

冻结后第一次复盘：`FREEZE_TS + 30 天`。
届时若 `MIN_EVENTS` 未达，结论是"**无结论，继续积累**"——不许因为
"等了 30 天总得说点什么"而降低判据。
